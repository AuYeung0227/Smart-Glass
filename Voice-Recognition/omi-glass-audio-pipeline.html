Stage 0

总览：三级缓冲流水线

整条链路跑在 loop_app() 的单线程轮询里，没有 FreeRTOS 任务。数据依次经过三块环形缓冲：i2s_read_buffer（采集）→ pcm_ring_buffer（编码前排队）→ audio_tx_buffer（发送排队）。每轮 loop 依次调用 mic_process()、opus_process()、processAudioTx()。

Stage 1

麦克风接收：I2S PDM 采集

XIAO ESP32S3 Sense 板载 PDM 数字麦克风，挂在 GPIO41（数据）与 GPIO42（时钟）。I2S 外设工作于 MASTER | RX | PDM 模式，硬件内部把 1-bit PDM 流滤波成 16-bit PCM，经 8×256 的 DMA 环形缓冲不间断搬运。

Stage 2

Opus 压缩与编码

PCM 先进入 500ms 的 pcm_ring_buffer 解耦采集与编码；opus_process() 每攒够 320 样本（20ms）取一帧，交给 Opus 库压成最多 160 字节的包。编码器参数：16kHz 单声道、VOIP 应用、32kbps、复杂度 3、可变码率。

Appendix C

注意事项

三级缓冲是「吸收抖动」，不是异步并发

整条链路在同一个 loop_app() 单线程里轮询，中间两级环形缓冲主要吸收瞬时抖动（如 BLE notify 瞬间阻塞），编码与发送靠每轮 loop 的 while 循环尽力排空。

mulaw.h 是死代码

linear2ulaw() 定义了 μ-law 编码器，但全工程无任何调用点，当前固件 100% 走 Opus，是遗留或低带宽备选方案。

编码 ID 注释自相矛盾

opus_encoder.cpp:169-174 注释写「Codec ID 20 = Opus」「Actually Omi uses 21」，实际返回 AUDIO_CODEC_ID = 21，生效值是 21。
